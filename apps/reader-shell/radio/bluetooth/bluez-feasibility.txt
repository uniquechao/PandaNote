Old-kernel boundary
The README4.9 minimum occurs under 'Kernel Build Options(for Mesh)', which is
explicitly disabled. Core adapter initialization checks MGMT major>=1 and several
new features have MGMT-version gates. This is promising static compatibility for
4.4.94, not target execution proof. Our standalone probe gathers actual controller
and kernel support after separately reviewed initialization. Subsequent daemon,
GATT registration/security, kernel crypto and phone behavior still require tests.

Stock initialization static proof
The reconstructed non-boot kernel ELF has builtin hci_uart/H4/socket init/functions,
so stock firmware does not require a separate hci_uart.ko. The btlpm module depends
on aic8800_bsp and registers rfkill initially software-blocked; its callback invokes
aicbsp_set_subsys(0, blocked?0:1). Thus rfkill writes trigger shared BSP behavior and
are not a passive permission change. Stock script also resets PE24/PD31/PA7/PC8;
BSP originally configures shared PB20/PB19/PE24/PA07/PD31/PD30. No such operation
was executed here. Root must review shared Wi-Fi ownership before BT activation.
Stock script then uses btattach -S1500000 -B/dev/ttyS3(H4 default), rfkill unblocks
and hciconfig up. Our code does not reproduce this chain. BSP firmware remains
pinned read-only /module_driver/firmware; hardware chip/revision must come from
actual controller local-version/features and BSP's already-reviewed probe logs,
not filename guesses. No firmware/driver image or memory layout change is proposed.
